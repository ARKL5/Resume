# Boss 筛选值守与运维

本仓库的筛选进程是长时本机任务（单轮可持续数小时）。通过 `--watch` 将后台浏览器进程与前台事件值守解耦，实现零轮询消耗盯完全程。

## 值守循环

1. **启动或续守**：
   - 续守当前轮或首次启动：`uv run python src/boss_screen/__main__.py --watch`（不设短超时）。
   - 上轮已结束、显式开启新一轮：`uv run python src/boss_screen/__main__.py --watch --start`。
   - 进程在跑时从本轮 `流式筛选开始` 起回看日志并挂接，不会漏掉挂接空档内的暂停或结束记录；进程已退出且已有历史日志时，`--watch` 只报告上轮结果，不自动开新一轮。
2. **按返回码处置**：
   - **退出码 `0`（`值守结束：完成`）**：仅当日志记录 `筛选结果：完成` 且无未解除告警时返回 `0`。查询 `boss.db` 统计本轮各 `stage` 数量及新增 `ai_keep` 岗位并汇报。
   - **退出码 `2`（告警或非完成退出）**：按下方「现场排障」处置；人工恢复后再次执行 `--watch` 续守，直至退出码为 `0`。

完成标准：`--watch` 以退出码 `0` 跑完所有城市与关键词并输出统计汇报，或定位到需人工介入的阻塞点并附现场信息通知用户。

## 现场排障

筛选进程使用 Patchright 管理本机有头 Chrome，不开启 `9222` 调试端口，也不挂载第二个 CDP 客户端（避免额外 `Runtime.enable`）。排障只读检查 `screen.log`、`boss.db`，并由用户在原 Chrome 窗口操作。

- **`暂停等人`（验证、登录、接口异常、详情超时、点击异常或列表无进展）**
  1. 查看 `screen.log` 末尾的暂停原因，请用户在已打开的 Chrome 窗口检查当前页面。
  2. **人机验证或登录（自动确认恢复）**：用户在原窗口完成验证或登录，并让页面回到当前目标搜索页或重新点开当前目标岗位；筛选进程收到新的成功业务响应后输出 `目标业务已恢复，继续`，随后再次执行 `--watch` 续守。
  3. **未知接口异常、详情超时或点击失败（需显式放行）**：用户确认原窗口目标列表或详情已恢复正常后，发送 `kill -USR1 $(cat .boss-screen.lock)` 放行，并在日志出现 `目标业务已恢复，继续` 后执行 `--watch` 续守；若疑似账号限流或封控，直接 `kill -INT $(cat .boss-screen.lock)` 结束本轮。
- **`停止本轮筛选` / `筛选结果：熔断`（进程已收尾退出）**
  - **AI 连续 3 次失败**（标题初筛、详情 JD、启动补评共用计数）：检查 `boss.yaml` 中 `ai.baseUrl` 服务连通性；恢复后用 `--watch --start` 开启新一轮（库内已抓正文的待评记录会在启动时零网页点击优先补评）。
  - **`onRisk: stop` 触发停机**：先根据日志原因确认是否为验证或接口限制，再决定是否用 `--watch --start` 重开。
- **`值守告警`（日志连续 300 秒无更新）**
  1. 检查 `.boss-screen.lock` 对应 PID 是否存活，并请用户查看 Chrome 窗口状态。
  2. 需停止时发送 `kill -INT $(cat .boss-screen.lock)`，等待日志写出 `筛选结果：人工停止` 并释放锁；确认需重开时用 `--watch --start`。

## 调优与回拨重评

用户修改 `boss.yaml`（关键词、黑名单、规则词、候选人画像或 Prompt）后：

1. **抽检停因**：`boss.db` 为 WAL 模式，可在运行期直接并发查询各 `stage` 的 `company, job, reason` 复盘误杀或漏杀。
2. **回拨状态（仅使用 `src/boss_screen/rules.py` 中 `PLACED_STAGES` 定义的合法值）**：
   - **零点击重评 JD**：对已有正文的记录（`trim(jd) != ''`），将 `stage` 更新为 `'ai_jd_pending'`。下次启动时 `_retry_pending_jds()` 会在打开网页前直接后台重评。
   - **重评标题初筛**：将无正文的被淘汰/含糊记录 `stage` 更新为 `'ai_title_pending'`，下次列表刷到时重新调用标题 AI。
3. **重启生效**：`boss.yaml` 在启动时加载。若筛选进程在跑，执行 `kill -INT $(cat .boss-screen.lock)` 等待收尾退出，再执行 `--watch --start` 启动新配置。

完成标准：`boss.db` 目标记录已更新为合法待评状态，且新配置已通过重启筛选进程生效。
