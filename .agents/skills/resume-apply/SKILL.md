# 投递流水

词见 [`CONTEXT.md`](../../../CONTEXT.md)。分列与人机分工见 [`docs/adr/`](../../../docs/adr/)。工具分类见 [`docs/apply-research.md`](../../../docs/apply-research.md)。

助手改清单和开放题草稿。用户装插件、登录、点提交。

硬约束：不收密码或 cookie；不写爬虫、选择器或绕过检测；不编仓库没有的经历；不自动回 HR 第二句；不在用户已登录的浏览器里代点提交或代装扩展；不把代提交或代聊工具写成用法。

项目链接：`https://github.com/ARKL5/retail-bench` 、 `https://github.com/ARKL5/rag-backend`

当次草稿：[`.notes/trial-list-2026-09-18.md`](../../../.notes/trial-list-2026-09-18.md)

字段：公司｜标题｜链接｜列｜城市/远程｜投递件｜项目链接｜试用工具｜状态｜下一步

按顺序做。前一步未完成，不开始下一步。

## 1. 确认清单

用户逐条确认：公司、标题、链接、列、哪份投递件、项目链接。未确认的行不是清单，不进档。

例外写在当次草稿该行。字节校园站但立刻实习等入口与附件不一致时，等用户拍板。

**完成：** 当次草稿里每一条都有用户的「进 / 去掉 / 改附件」；未确认的行不进入第 2 步。

## 2. 档 1 官方填表

两家企业官网。试用牛客网申助手，只填结构化字段。开放题只写 [`.notes/oral-source-material.md`](../../../.notes/oral-source-material.md) 能撑住的句子；数字回指 artifact；口述用「评测仪器」；92/114 只描述该 artifact，不是 HEAD KPI。PDF 里仍有、仓库撑不住、不写进开放题：「分别验证 System Prompt 与 Tool Description」「预演在独立内存副本中校验」。

开放题草稿用户提交前必看。

**完成：** 该档每一条：结构化字段已填、开放题草稿用户已看、用户声明已提交或跳过。

## 3. 档 2 第三方填表对照

一家企业官网。试用塔塔网申（对照可用超级网申），只填结构化字段。开放题规则同第 2 步。写下与牛客助手字段是否一致。

**完成：** 对照结果已记在该行；开放题草稿用户已看；用户声明已提交或跳过。

## 4. 点投手投

清单里点投行（实习僧「投个简历」等）。无插件代点。

**完成：** 每条点投行用户声明已点或跳过。

## 5. 档 3 Boss 开聊

用户从已登录 Boss 粘贴杭州 + Agent/LLM 应用实习（每周 5 天）后，过滤再进清单。主号每天个位数。出现限流、验证码墙或投诉则停止该档。

只发第一句 + 简历。HR 回了用户接手。秋招网申走主身份。发出前看输入框是否截断：

> 您好，浙江理工大学，常驻杭州，每周 5 天，随时到岗。独立做过零售客服 Agent：在 tau2-bench 上做确定性评测和优化，任务通过率80.7%（92/114），另有用户隔离的可靠 RAG 后端。期待沟通。

**完成：** 粘贴岗位均已进清单或标不进；已发开聊为个位数且仅第一句；若已出现限流 / 验证码 / 投诉，该档已停。
