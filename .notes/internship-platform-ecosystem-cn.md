# 分平台生态 + 校招 / 企业网申填表脚本

- 调研日期：2026-09-18
- 承接：`.notes/internship-batch-apply-cn.md`（投递模型 / 协议）与 `.notes/internship-apply-plugins-cn.md`（官方 vs 第三方、代聊）
- 范围：只补「每个平台现成工具能代劳到哪一步」和「企业网申 / 校招填表脚本分类」。协议全文、海投商店清单、Boss 高星打招呼仓，前两份已写，这里不抄。
- 方法：打开校招官网 HTML、Chrome / Edge 商店页、GitHub README、插件官网、ATS 厂商公开页、平台协议。二手帖只当线索。
- 硬约束：不写可运行代码、选择器、接口、验证码绕过；不登录、不投递；不把自动打招呼说成官方功能。
- 证据规则：主张回溯到一手来源。搜不到写「未找到」。

用户已锁的操作模型（判断「和他相关」的尺子，不是给工具开脱）：

1. 本人确认清单（公司、链接、实习 / 秋招、哪份 PDF、项目链接）。
2. 登录态只在他自己的浏览器；他自己跑现成开源脚本 / 插件。
3. Boss 默认开聊放进机械队列：脚本只发第一句 + 简历；HR 回了由他接手。可接受封号、准备备用号；秋招网申用主身份。
4. 渠道排序：可自动化 × 供给 × 封号成本，不是只看脚本多不多。
5. 校招点名：企业网申表格填写也有对应脚本，须核实并分类。

「官方」= 该招聘平台或该简历产品自己发布。  
「第三方」= 不是目标招聘站发布。  
「只填表」= 公开描述是把已有信息填进表单，提交仍须本人点。  
「声称填开放题」= 公开描述会生成 / 填写问答题、自我评价、职位匹配说明等非结构化字段。  
「声称代提交」= 公开描述会替用户点提交、点投递、或一键完成申请。

## 0. 一页结论（和他模型对齐）

| 他要的动作 | 现成工具能代劳到哪 | 仍必须本人 |
|---|---|---|
| 确认投谁、投哪条链接、用哪份 PDF | 无。清单确认是闸门 | 全部 |
| 实习僧点「投个简历」 | 无合规代点。第三方仓声称能代点，违 ToS | 筛完后人手点 |
| Boss 开聊第一句 + 简历 | 第三方打招呼脚本 / 扩展**声称**能发第一句并附简历；无官方插件。协议禁止 | 清单确认、HR 回了接手；秋招不要用主身份跑这类工具 |
| Boss「网申·直投」校招岗 | 官方按钮自己点；表单复用是官方能力 | 认标识、点直投 |
| 智联校园 / 社招点投 | 官方「智能投递」有配额；第三方代点违 ToS | 校园申请表每家检查后提交 |
| 51Job / 应届生点投 | 无官方批量。超级网申点名这两站，但是对它们仍是未经许可的第三方插件 | 人手点「立即投递」 |
| 企业官网 / 北森 / Moka 网申填表 | **有成熟填表插件**（官方：牛客、实习僧网申助手、超级网申；第三方：塔塔、TalenCat、求职方舟等） | 开放题、附件、诚信勾选、点提交 |
| 阿里 / 蚂蚁 / 字节 / 网易官网 | 填表插件声称覆盖这些站的结构化字段；四家公开页是**自研 ATS**，不是北森 / Moka | 意向选择、开放题、提交；秋招用主身份 |
| 高校 / 24365 | **未找到**针对该系统的填表 / 代投脚本 | 学号登录后点投 |

渠道排序（自动化 × 供给 × 封号成本，不是脚本数量）：

1. **企业官网网申 + 智联校园申请表**：供给是秋招主战场；官方 / 第三方填表插件成熟；提交本人点，封号成本主要在「插件注入目标站」而不是 Boss 式封号。适合主身份。
2. **实习僧 / 51Job / 应届生点投**：供给大、模型是提交申请；官方没有批量点投；第三方代点违 ToS。适合清单确认后人手点，不要指望脚本海投。
3. **Boss 开聊队列**：供给最大、第三方脚本最多，封号成本也最高。和他模型匹配的是备用号 + 第一句 + 简历，HR 接手；**不要**用秋招主身份跑打招呼脚本。
4. **猎聘点「投简历」**：模型符合点投，第三方脚本少、实习供给小于 Boss / 实习僧。
5. **拉勾**：本次主站 / 协议页仍被阿里云 WAF 拦截，产品按钮未钉死；投投马等声称支持，协议禁插件。排序靠后。
6. **高校 / 24365**：点投模型正确，无填表脚本生态，必须本人登录点。

## 2. Boss 直聘 https://www.zhipin.com

### 1. 站内原生动作

默认开聊（「立即沟通」）。开聊 ≠ 申请；附件简历须一方发起、另一方同意才发送。校招岗另有「网申·直投」：可直接投简历，表单由已有简历解析。来源：BOSS 官方账号 2026-03-04 春招说明书 https://view.inews.qq.com/a/20260304A045PY00

### 2. 官方加速

- 「网申·直投」是岗位类型，**不是插件**。表单复用是官方能力。
- **未找到** Boss 官方打招呼插件 / 官方海投扩展。协议第十三条只写平台可限制收发沟通数量。

### 3. 第三方生态（针对 Boss）

成熟度在国内招聘站里**最高**，而且几乎全是代聊 / 代投，不是填表。

- Chrome：投投马、BOSS海投助手、职投助手等（前篇 3.3）。公开功能是自动打招呼或投递。
- 油猴 / GitHub（star 为调研当日公开页，会变）：`Ocyss/boss-helper` 约 2.2k；`yangfeng20/ai-job` 约 2.1k；`longsizhuo/BossZhiPin_Job_Search` 约 1.4k。声称批量开聊 / 发招呼 / 有的再发简历。
- **针对 Boss 网申表单的填表项目：未找到独立高星仓。** 直投岗走官方解析，不需要第三方填表。

### 4. 校招表格

直投岗：结构化简历解析，固定信息可复用。默认岗：无申请表，是会话。开放题不是 Boss 主路径。

### 5. 和他模型的匹配

和他锁死的队列一致：脚本只发第一句 + 简历，HR 回了接手。现成第三方工具**声称**能做这一步，但全部落在 Boss 第八条 10 / 13 / 14 款。官方不能代劳开聊。  
必须本人：确认清单、认「网申·直投」标识、HR 回复后的对话、秋招主身份不要用来跑打招呼工具（备用号承担封号）。脚本多 ≠ 渠道优先：供给大、可自动化高、封号成本也最高。

  校园帮助还写：申请表投递后企业一旦处理即不能改。https://xiaoyuan.zhaopin.com/PublicPage

条款惩的是**虚假信息**和**本人承诺**，没有写「禁止用插件填姓名学校」。把 AI 生成的开放题直接提交，落在「虚假 / 不准确资料」「本人承诺」的语义里——这是条款已写的，不是用法指导。

## 12. 信息缺口

1. 阿里中文 FAQ 的「造假取消资格」原句：本次只钉死英文 FAQ。中文 SPA 无稳定正文。
2. 蚂蚁、网易公开诚信承诺长文：**未找到**。
3. 塔塔、互联派、OfferLink、求职喵的完整商店正文：部分依赖检索摘要 / chrome-stats，不是每次都打开全文。
4. 超级网申是否生成开放题：商店已核字段列表不含开放题；二手「智能回答开放题」未在商店页钉死。
5. 牛客助手在阿里 / 字节**当前**自研页上的实际填充率：商店点名这些公司，未登录无法测。
6. 某具体公司网申是北森、Moka 还是自研：须看该次打开的 URL / 页脚，不能从公司名推断。四家大厂本次已用 HTML 指纹钉死为自研。
7. 拉勾职位按钮、高校就业网登录后字段：须本人过验证 / 学号登录。
8. CampusApply-Agent 仅 1 commit，README 声称覆盖北森 / Moka / 智联——**不能**当成已验证可用。
